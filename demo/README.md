# Как кнопка запускает сдачу домашки

Это исполняемый прототип архитектуры. Он работает локально: вместо устройства команда `PRESS`, вместо браузера — имитация LMS. Вход в аккаунт и реальная отправка файлов не реализованы.

## Запуск

Нужен Node.js 18 или новее. Зависимостей нет. Команды выполняются из корня репозитория:

```sh
node demo/run.mjs
node demo/run.mjs --double-press
node demo/run.mjs --fail=upload
node demo/run.mjs --fail=verify
node --test demo/scenario.test.mjs
```

Обычный запуск показывает успешный сценарий. `--double-press` показывает блокировку второго нажатия во время выполнения. `--fail` имитирует ошибку на этапе `check`, `upload`, `submit` или `verify`; программа завершается с кодом 1.

Пример вывода:

```text
[Кнопка → ПК] PRESS
[ПК → кнопка] BUSY
[Сценарий] Файл найден. Проверяем вкладку и выбранное задание.
[Сценарий] Прикрепляем файл.
[Сценарий] Выполняем окончательную отправку.
[Сценарий] Проверяем подтверждение сдачи.
[ПК → кнопка] SUCCESS
```

## Где находится логика

```text
Физическая кнопка (будущее устройство)
    │ USB Serial: PRESS\n
    ▼
run.mjs — сейчас имитирует получение команды
    ▼
scenario.mjs — проверка файла, порядок действий, блокировка повторного запуска
    ▼
mock-lms.mjs — сейчас имитирует вкладку, загрузку и проверку сдачи
    │
    └── результат → SUCCESS\n или ERROR\n → подсветка устройства
```

- `config.json` привязывает событие нажатия к сценарию `submit-homework`, файлу и ссылке на задание. Путь файла считается относительно папки `demo`, независимо от текущей рабочей папки терминала. `id=DEMO` — заглушка.
- `scenario.mjs` принимает `PRESS` и последовательно вызывает методы адаптера LMS. Успех возможен только после подтверждения статуса `submitted` именно для выбранного задания.
- `mock-lms.mjs` показывает контракт будущего расширения браузера: `checkAssignment`, `uploadFile`, `submit`, `verifySubmission`. Он не проверяет реальную доступность или устройство LMS AITU.
- `fixtures/homework.txt` — пример файла.

## Подключение настоящего устройства и LMS

1. Прошивка микроконтроллера отслеживает нажатие с подавлением дребезга и отправляет строку `PRESS\n` по USB Serial.
2. Программа на ПК собирает полные строки из входящего потока и передаёт их в `controller.receive(...)`. Callback `send` записывает ответ в тот же порт: `BUSY\n`, `SUCCESS\n` или `ERROR\n`.
3. Прошивка показывает занятость, успех или ошибку подсветкой. Повторное нажатие во время работы игнорируется контроллером; текущий статус устройства сохраняется.
4. Вместо `createMockLms()` подключается адаптер программы и расширения браузера, работающий с уже авторизованной вкладкой. Команды и подтверждения привязываются к конкретной вкладке и заданию. Пароль в конфигурации не нужен.
5. Реальные селекторы, передача файла в расширение и финальное подтверждение сдачи разрабатываются после осмотра конкретного задания LMS. Нужны таймауты и проверка существующей сдачи перед повторной отправкой.

Блокировка этого прототипа действует только во время одного запуска. Последующее нажатие снова запускает сценарий. Если отправка прошла, но подтверждение потерялось, реальный адаптер должен сначала проверить статус задания: автоматический повтор может создать дубликат.

Лендинг в корне репозитория пока независим от этих скриптов. Нажатие красной кнопки на сайте запускает только визуальную анимацию.
